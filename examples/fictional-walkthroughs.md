# Fictional walkthroughs

These examples are invented for this public case study. They are not real reviews, customer records, prompt transcripts, or original workflow data. Product and policy details are deliberately generic.

## 1. Routine praise

**Illustrative input:** “The desk lamp arrived on time and is easy to set up.”

The review enters a source-specific n8n workflow and is routed as routine feedback. A draft follows the relevant response template and brand tone. In daytime mode, the operator approves or edits it. Outside working hours, an eligible routine response can take the automatic path. The publisher then confirms the channel's publication result. The exact eligibility rules from the historical system are unknown.

## 2. Photo suggesting a defect

**Illustrative input:** “The lamp shade looks cracked,” with a fictional image attachment.

Vision AI may flag a possible defect. It does not make the final finding. A product expert confirms or rejects the defect interpretation before any defect-specific response. If a remedy is appropriate, its alternatives come from deterministic calculations and current policy, not from invented LLM arithmetic. An LLM can help compare ambiguous product references when needed. A brand-guided response is then reviewed or routed according to the operating mode and applicable safeguards.

## 3. Technical publication failure

**Illustrative event:** A browser-based publishing task submits an answer, but the service cannot verify that it appeared on the site.

The task is treated as an error, not as a published reply. The system notifies the operator, who investigates and fixes the issue manually. This example intentionally contains no automatic retry or self-healing step. For Ozon, Wildberries, and Telegram API paths, the corresponding confirmation signal was the API response.
